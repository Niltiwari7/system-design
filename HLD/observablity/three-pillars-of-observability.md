## Three pillars of observability
1. Logs
2. Metrics
3. Traces

> Metrics tells what is wrong. Logs tell what happened. Traces tells where it happened.

### 1. Metrics
Metrics are numerical measurements collected over time.

Examples:
```
CPU usage        = 72%
Memory usage     = 80%
Request rate     = 2,000 req/sec
Error rate       = 2.5%
p95 latency      = 350 ms
```

Imagine our API:
```
Users
  ↓
API Server
  ↓
Database
```

we might monitor:
```
Requests/sec
   ↓
2000

Error rate
   ↓
0.5%

p95 latency
   ↓
250ms
```
Why metrics?

Metrics are excellent for answering:

> **"Is my system healthy"**

Common metrics:
Infrastructure
- CPU
- Memory
- Disk
- Network


Application
- Request rate
- Error rate
- Latency
- Active connections

Business
- Orders/minute
- Payments/minute
- Signup rate
- Revenue

###  2. Logs
Logs are events or records generated by our application/system.

Example:
```
2026-10-06 03:20:15
INFO
User 123 created order 456
```

Another
```
2026-10-06 03:20:18
ERROR
Payment failed
orderId=456
provider=Stripe
reason=timeout
```

Logs answer:
> What exactly happened?

### 3. Traces
Traces are especially important is distributed systems/microservices.

Imagine:
```
User
 ↓
API Gateway
 ↓
Order Service
 ↓
Payment Service
 ↓
Database
```

One request travels through multiple services.

A trace lets follow that single request across entire system.

### Complete observability flow

```
                     APPLICATION
                         |
             ┌───────────┼───────────┐
             ↓           ↓           ↓
          Metrics       Logs       Traces
             ↓           ↓           ↓
          Prometheus    Loki       Jaeger
             ↓           ↓           ↓
             └───────────┼───────────┘
                         ↓
                    Dashboard
                         ↓
                       Alert
                         ↓
                     Engineer
```
